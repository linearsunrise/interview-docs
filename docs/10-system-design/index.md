## Тренировочные задачи (проговаривать вслух, 35–45 мин каждая)

1. **URL shortener** — генерация ключей (счётчик+base62 vs hash), редирект 301 vs 302 (аналитика!), кеш, счётчики кликов
2. **Лента новостей** — fan-out on write vs read, гибрид для селебрити, пагинация ленты
3. **Чат** — WebSocket-шлюзы, доставка офлайн-пользователю, порядок сообщений, статусы прочтения, шардирование по чатам
4. **Система нотификаций** — приоритеты, каналы, дедупликация, retries, rate limit на пользователя
5. **Платёжная система** — идемпотентность, outbox, saga с провайдером, реконсиляция, ledger (append-only)
6. **Booking (отели/билеты)** — конкурентный резерв: блокировки vs optimistic, TTL-холды, овербукинг
7. **Rate limiter как сервис** — алгоритмы, Redis, точность vs производительность
8. **Загрузка и раздача файлов** — presigned URLs, chunked upload, CDN, дедупликация

## Ключевые тезисы

**Структура ответа (повторять на каждой задаче):**
1. Требования и уточнения (5 мин): кто пользователи, какие сценарии, масштаб, что важнее — консистентность или доступность
2. Оценки (5 мин): RPS чтение/запись, объём на год
3. High-level (10 мин): клиенты → LB → API → сервисы → хранилища → очереди; нарисовать
4. Deep dive (15 мин): 1–2 самых интересных места (схема данных, горячий путь, консистентность)
5. Узкие места и эволюция (5 мин): SPOF, шардирование, деградация

**Главная ошибка кандидатов** — прыгать в детали без требований и цифр. Вторая — «везде Kafka и микросервисы» без обоснования.

**CAP на практике:** при сетевом разделении выбираем: отвечать возможно устаревшими данными (AP) или отказывать (CP). Для платежей — CP-поведение критичных операций; для ленты — AP.

## Красные флаги

- Начинает рисовать архитектуру до вопросов о требованиях
- Не может оценить нагрузку даже грубо
- Одна БД «на всё» без обсуждения роста, или наоборот — 10 технологий без причин
- Не упоминает failure modes: «а что, если этот компонент упадёт?»

## Практика

- 6–8 задач из списка вслух с таймером, лучше с партнёром или записывая себя
- Для каждой — конспект на страницу в этот док: схема + ключевые решения + trade-offs
