# WeakMap, WeakSet, WeakRef

> **TL;DR:** `WeakMap`/`WeakSet` держат ссылки на объекты **слабо** — это не мешает сборщику мусора удалить объект, если на него нет других сильных ссылок. Ключ (`WeakMap`) или элемент (`WeakSet`) — только объект, не примитив. Осознанная плата за это: коллекции **не перечисляемы** — нет `.keys()`, `.size`, `for...of` — потому что порядок и момент сборки мусора не детерминированы спецификацией, и делать их наблюдаемыми через перечисление значило бы утечь детали реализации GC в семантику языка.

## Зачем нужны — привязка метаданных к жизни объекта

```js
const cache = new WeakMap();
function process(obj) {
  if (cache.has(obj)) return cache.get(obj);
  const result = heavyCompute(obj);
  cache.set(obj, result);
  return result;
}
// когда obj больше никто не держит — запись в WeakMap исчезнет сама,
// в отличие от Map, где cache.set(obj, ...) удержит obj вечно, пока не сделать delete вручную
```

Это главное отличие от обычного `Map` как кэша: `Map` — источник утечки, если ключи не вычищать руками (классический пункт из чек-листа по утечкам, см. [Поиск утечек памяти](../02-nodejs-core/08-memory-leaks.md)); `WeakMap` сам не мешает объекту умереть.

## Приватное состояние до `#private`-полей

```js
const _state = new WeakMap();
class Store {
  constructor(initial) { _state.set(this, initial); }
  get() { return _state.get(this); }
}
```

Инстанс `Store` невозможно интроспектировать через `Object.keys`/JSON — состояние физически не на самом объекте. Сейчас для этого чаще используют `#private`-поля (см. [Прототипы и class](./03-prototypes-and-classes.md)), но паттерн WeakMap остаётся стандартным ответом на "как эмулировать приватность до ES2022" и годится, когда состояние прикручивается к объекту **извне** (библиотека добавляет метаданные к чужому объекту).

## `WeakSet` — пометка "видели ли мы этот объект"

```js
const visited = new WeakSet();
function serialize(obj) {
  if (visited.has(obj)) throw new Error('circular reference');
  visited.add(obj);
  // ...
}
```

## `WeakRef` и `FinalizationRegistry` — низкоуровневый инструмент, не для бизнес-логики

```js
const ref = new WeakRef(bigObject);
ref.deref(); // bigObject, либо undefined, если уже собран GC
```

`FinalizationRegistry` позволяет зарегистрировать колбэк на "объект собран" — но спецификация **прямо предупреждает**: нет гарантий, что колбэк вызовется вообще (например, если процесс завершится раньше). Использовать это для управления ресурсами (закрытие файлов, соединений) — антипаттерн; для интервью важно знать, что это существует и почему им почти никогда не пользуются в прикладном коде (профилировщики, кэши с ручным контролем — редкие легитимные кейсы).

## Что спрашивают на собеседовании

1. **Почему `WeakMap` не имеет `.size` и не итерируется?** — момент сборки объекта недетерминирован; если бы `.keys()` существовал, поведение программы зависело бы от того, когда именно отработал GC — не воспроизводимо.
2. **Чем `WeakMap`-кэш лучше обычного `Map` для метаданных к объектам?** — не удерживает ключи от сборки мусора: запись исчезает сама вместе с объектом, не нужно вручную чистить.
3. **Может ли ключом `WeakMap` быть строка или число?** — нет, только объект (и, начиная с ES2023, символы, кроме registered symbols) — примитивы не участвуют в GC так, чтобы "слабость" ссылки имела смысл.
4. **Когда стоит использовать `WeakRef`/`FinalizationRegistry`?** — почти никогда в прикладном коде; нет гарантии вызова и таймингов — не заменяет `try/finally` или явное освобождение ресурсов.
5. **Как эмулировать приватные поля класса без `#`-синтаксиса?** — модульный `WeakMap`, где ключ — инстанс, значение — приватное состояние, недоступное снаружи модуля.
