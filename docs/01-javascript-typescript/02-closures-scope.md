# Замыкания и лексическое окружение

> **TL;DR:** Замыкание — это не «функция, которая помнит переменные», а функция, которая держит **ссылку на своё лексическое окружение** (Environment Record), а окружения образуют цепочку по месту объявления в коде (не по месту вызова). Отсюда: захватывается не значение, а сам биндинг — если он поменяется после создания замыкания, замыкание увидит новое значение.

## Как это устроено

У каждой функции есть внутренний слот `[[Environment]]` — ссылка на окружение, в котором она была **объявлена**. При вызове создаётся новое окружение для локальных переменных, а его "родителем" ставится `[[Environment]]` — так строится scope chain. Поиск переменной идёт вверх по цепочке, пока не найдётся биндинг или не кончится глобальная область.

```js
function makeCounter() {
  let count = 0; // живёт в окружении makeCounter, а не на стеке
  return () => ++count; // замыкание держит ссылку на это окружение
}
const counter = makeCounter();
counter(); // 1
counter(); // 2 — то же окружение, не пересоздаётся
```

Стек-фрейм `makeCounter` формально завершился, но его переменное окружение не уничтожается GC, пока на него есть ссылка (из возвращённой стрелочной функции) — переменные "живут" дольше вызова.

## `var` vs `let` в цикле — классическая задача

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 3, 3, 3 — var функционально-scoped, один биндинг на весь цикл

for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 0, 1, 2 — let блочно-scoped: спецификация создаёт НОВЫЙ биндинг i на каждую итерацию
```

Это не «компилятор копирует значение» — буквально по спеке `for (let ...)` на каждой итерации создаёт новое лексическое окружение с новым `i`, инициализированным значением из предыдущей итерации. `var` создаёт один биндинг на всю функцию, все замыкания в цикле делят одну и ту же ячейку.

## Практическое применение

**Приватное состояние (до `#private`-полей):**

```js
function createStore(initial) {
  let state = initial; // недоступно снаружи напрямую
  return {
    get: () => state,
    set: (next) => { state = next; },
  };
}
```

**Мемоизация:**

```js
function memoize(fn) {
  const cache = new Map(); // захвачен замыканием, живёт между вызовами
  return (arg) => cache.has(arg) ? cache.get(arg) : cache.set(arg, fn(arg)).get(arg);
}
```

## Опасность: утечки памяти через замыкания

Если долгоживущая структура (глобальный массив, event emitter, кэш) держит колбэк, а колбэк — замыкание с ссылкой на большой объект (даже случайно, через общий scope), объект не соберётся GC, пока жив держатель колбэка. Частый паттерн утечки: `emitter.on('event', () => useObj(bigObject))` без последующего `off()`. Подробный разбор диагностики — в [02-nodejs-core/08-memory-leaks.md](../02-nodejs-core/08-memory-leaks.md).

## Что спрашивают на собеседовании

1. **Что выведет цикл с `var i` и `setTimeout` внутри?** — `3, 3, 3`; объяснить через один биндинг vs новый биндинг на итерацию у `let`.
2. **Что такое замыкание технически?** — ссылка функции на лексическое окружение объявления (`[[Environment]]`), а не «снимок» значений переменных.
3. **Как замыкание может привести к утечке памяти?** — колбэк в долгоживущем держателе (emitter, таймер, кэш) удерживает всё окружение, включая ничем не нужные большие объекты из того же scope.
4. **Реализуйте приватный счётчик без классов** — через замыкание, возвращающее объект с методами, читающими/пишущими внешнюю переменную.
5. **Почему `let` в цикле "чинит" проблему с `var`, а не просто "работает лучше"?** — конкретный механизм: per-iteration lexical environment у `let`/`const` в `for`, а не общее для всей функции окружение у `var`.
